# 游戏卡顿验证 · 2026-10-23

已定位并消除可重复出现的约半秒停顿：小妖第一次需要绕过障碍追逐人物时，`World.steer` 会在单帧同步计算整关的导航网格。真实浏览器采样将 501.6 ms 定位到该函数；存档、术法和画面绘制均不是这一停顿的主因。

现在把原算法计算的全部 42 关可行走节点和八方向连边预先保存，运行时校验地形指纹后按需解码。运行中的精确碰撞、妖的数量、伤害、施法和特效均保留。缓存约 214 KB，仅保留最近三关的解码结果；文件缺失或地形发生变更时仍能使用原算法。

| 固定负载 | 无缓存：CPU 最坏帧 | 有缓存：CPU 最坏帧 | 有缓存：CPU p95 / p99 | 有缓存：画面最坏帧 |
| --- | ---: | ---: | ---: | ---: |
| 空场景 | — | 1.3 ms | 0.9 / 1.1 ms | 17.8 ms |
| 64 妖 | 489.3 ms | 14.3 ms | 11.4 / 12.9 ms | 29.4 ms |

同一台电脑、Edge 无头浏览器、1440×1000 视口、最终关噩梦难度、固定随机种子、每次模拟 1/60 秒、八种高阶术法、持续摇杆移动；预热 90 帧后采样 240 帧。固定妖数并提高敌人生命、人物无敌，以持续运行实际更新/绘制路径。对照只关闭导航缓存：64/128 妖都稳定重现约半秒停顿。两次测试最终粒子数相同，分别为 274 / 357。

验证命令：

```text
node tools/check-performance-ui.js --label=control-no-cache --counts=64,128 --no-navigation-cache=true
node tools/check-performance-ui.js --label=final --verify-topology=true
node tools/build-navigation-cache.js --check
node tools/build-navigation-cache.js --verify

```

第一条对照命令预期失败，其余通过。Node 和 Edge 均已核对 42 关全部节点及每条有向连边，与原算法完全一致；另通过 210 项世界几何检查。跨引擎三角函数的最后一位浮点差异通过六位小数的几何指纹规整处理，避免相同地形误判缓存过期。修改地形之后运行 `node tools/build-navigation-cache.js` 重新生成缓存。

曾测试静态多边形空间分桶，但未消除该尖峰，已从最终代码移除。完整基线、定位数据、被否定的实验与最终数据记录在 `流畅性验证-20261023.json`。

此结果说明已修复本机可重复的半秒停顿，不保证所有设备固定 60 FPS。128 妖持续全术法压力下，CPU p95 仍约 20 ms；这些压力测试也不代表人工通关率。
